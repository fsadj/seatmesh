## 阶段一 · 质量地基 + 契约冻结 + 数据地基

**需求**

1. `sre/stress.py`（threading 并发版）：90% 查询 + 10% 并发抢同一座位；
   断言 `成功响应数 == 1 且 double_assign == 0`，末行 `OVERSELL_CHECK: PASS/FAIL`。
   "成功"以**响应**计数（拒绝事件也在事件流里，不能数事件）。
2. `sre/audit.py` 审计器：订阅事件流维护影子位图，断言 I1（成功 RESERVE 的 mask
   与施加前位图无重叠）；violation > 0 非零退出；测试里伪造重叠双预约事件，
   验证审计器抓得到——抓不到坏人的审计器不算审计器。
3. CI `.github/workflows/ci.yml`：`make test-engine` → `make demo-python` →
   `pytest gateway/tests ai/tests` → `python sre/stress.py --quick`；Makefile 目标 `ci`。
4. 契约冻结评审会：走读 docs/09、docs/13（epoch 2）、compat-notes、三份契约文件、
   JSON 帧格式 v0；产出《签字表》（T1–T5 五行）全签；此后契约变更走流程（你是汇总人）。
5. 数据管道 `ai/pipeline.py`：
   - 表 `events_raw(ts_ms, seq, type, user_id, seat_id, day_off, mask, detail)`，
     mask 以字符串存储（大整数）；
   - 视图 `v_hourly(day, hour, occupancy)`：每小时被占片数 / 64；
   - `load_from_engine(stream, db_path, batch)` 批量入库；
   - `generate_synthetic(days, peak_hours)` 造数器：高峰小时 λ = 低谷 × 8 的泊松到达，
     行为分布 85% 预约（随机座位 + 连续 2–8 片）/ 10% 开始前取消 / 5% 超时爽约；
     同种子两次运行结果一致。

**交付物**：`sre/stress.py`、`sre/audit.py`、CI 文件、签字表、`ai/pipeline.py`。

**验收 DoD**：Actions 绿；注入用例 violation>0；造数高峰/低谷占用比 >2。

**保底**：stress + audit + CI（评审会不可保底，必须开）。

## 阶段二 · 一致性验证 + 混沌 + 预测/风控 + 报告

**需求**

1. `sre/jepsen.py` 两层检查器：
   - 不变量层（必做）：50 线程 × 60s 并发 reserve/cancel 同一座位，记录
     `(invoke_t, op, args, ok_t, result)` 到 `history.jsonl`；同 seat-day 成功
     RESERVE 区间两两不重叠；
   - 线性一致性层：按 seat-day 分键的 WGL 实现——成功操作构建 real-time 偏序，
     逐一搜索合法线性化点（单座位一天仅 64 位，状态空间可控）；
   - 输出 `docs/jepsen-report.md`：操作数/成功率/检查结论/异常历史。
2. 混沌剧本三则（`sre/chaos/`，各 ≤2 分钟演示完）：
   - `c1_kill_leader.sh`：3 节点压测 30s → kill leader → 复用 T2 的 failover 断言；
   - `c3_clock_skew.sh`：对 follower 做 faketime +2s → 断言服务不中断
     （只对 follower，leader 偏移是另一个刻意选主风暴剧本）；
   - `c4_disk_full.sh`：tmpfs 填满 WAL 分区 → 断言引擎拒绝写并告警 →
     清理后 replay 补齐。
3. 可观测：引擎 `/metrics` 接入核对（指标名与清单一致：
   `reserve_result_total / invariant_violations_total / raft_elections_total /
   apply_lag_entries / replica_staleness_ms / wal_fsync_queue_depth`）；
   `sre/observe.yml` 起 Prometheus + Grafana；面板含 SLO 99.9% 线与
   violations=0 面板。
4. 预测与风控：
   - `ai/train_occupancy.py`：从 `v_hourly` 取数；特征 = hour、weekday、
     lag-1d、lag-7d、是否高峰；LightGBM 回归；输出分时段 MAE 表（高峰/平峰/夜间）；
   - `forecast(model_path, date) -> list[tuple[slot, 0.0-1.0]]` 64 点；
     挂 `GET /api/forecast?date=`，进程内加载（<10MB），p99 <50ms；
   - `ai/train_noshow.py`：逻辑回归（历史爽约次数/提前时长/时段），输出 AUC；
     风险分挂 `GET /api/credit` 响应（`"risk": 0.73`）；
   - 评估报告 `docs/ai-eval.md`：数据来源、特征表、指标、**synthetic 数据训练的
     局限必须在首页写明**；LightGBM 不可用时降级分桶均值（同接口）。
5. `docs/bench-v0.9.md`：环境/场景/QPS/p99/0 超卖/恢复时间/副本 staleness，
   **每个数字附一键复现命令**，无脚本的数字不配出现在报告里。

**交付物**：`jepsen.py`、`sre/chaos/c1,c3,c4`、`observe.yml` + `dashboard.json`、
metrics 核对记录、训练脚本 + 评估报告、bench 报告。

**验收 DoD**：`make chaos-c1` 绿；报告数字他人可复现；forecast 压测 p99<50ms。

**保底**：不变量层 + C1 + bench（预测退化为静态均值表；WGL/C3/C4/Grafana 顺延）。

## 阶段三 · 全量回归 + 一致性终版 + 答辩材料

**需求**

1. `sre/regression.py`：干净环境（compose 起全套）自动执行核心 AC——
   0 超卖 / 崩溃恢复 / 故障接管 / 候补闭环 / 双区双抢 / 断网演练；
   每项输出 `{ac_id, pass, seconds, evidence_path}`；汇总 `docs/regression-v1.0.md`
   绿表（含环境指纹与总耗时）。
2. 一致性验证报告终版：jepsen（含 WGL 层）在双区部署重跑（叠加断网扰动），
   汇总 I1–I4 与线性一致性结论，随 tag v1.0 归档。
3. 答辩材料汇编 `docs/final/`：架构总览、bench 终版、jepsen 终版、回归报告、
   ADR 合集、AI 评估——一页目录索引串起全部。**各章节由全组按分工提交，
   你负责汇编、格式与数字核对（每个数字可溯源到报告）**。
4. 协助 T2 的 `make demo-reset` 验收（<5min）与两次带旁白录屏的检查。

**验收 DoD**：`make regression` 干净环境全绿；答辩包目录逐项可查。

**保底**：回归覆盖三项核心（0 超卖 / 崩溃恢复 / 故障接管）。
