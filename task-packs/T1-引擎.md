## 阶段一 · 状态机钉死与持久化加固


**需求**

1. 单测 `engine/tests/test_engine.cpp` ≥20 条（`FakeClock` 驱动），覆盖：
   预约成功置位；重叠拒绝且 `conflict_mask` 恰为交集；幂等重放返回原结果；
   参数非法 → `E_PARAM` 不落日志；入馆刷卡窗 `[时段开始, 开始+30min)` 内成功转
   `IN_LIBRARY`、窗外 `E_WINDOW`；当日 08:00 前申请截止 = 当日 08:30（特例断言）；
   越过截止后 `tick()` → NO_SHOW 事件 + 位图释放 + `credit=-10`；开始前 cancel 释放、
   开始后 cancel `E_WINDOW`；checkout 转 LEFT 且 `released_mask` 正确；
   `serialize_state`/`restore_state` 往返全等。
2. 幂等表 LRU 上限 100000，超限淘汰最旧，淘汰后同 `request_id` 按新请求处理。
3. WAL 轮转：`write_snapshot()` 成功后当前 WAL → `wal.1`（原子 rename），新开
   `wal.log`；`replay()` 按 `wal.1` → `wal.log` 顺序读，快照 index 前跳过；
   撕裂尾/CRC 错截断停止。
4. 幂等表入快照（条数 u32 + 每条两字符串），恢复后重复 `request_id` 仍拒。
5. `ZmqRouterSource` 实现：ROUTER 帧序 `[identity][payload]`，payload = JSON 帧 v0
   （与 T3 签字冻结）；`poll()` 非阻塞；应答 `[identity][json]`；JSON 转义完整
   （测试含引号 detail）；编译开关 `SEATMESH_HAS_ZMQ`。
6. `engine/scripts/crash_test.sh`：回放 3 请求 → `kill -9` → 重启 → 断言状态完整，
   输出 `RECOVERED OK`。

**交付物**：`test_engine.cpp`、engine 源码 PR、`crash_test.sh`。

## 阶段二 · 候补授权 + 中途离开 + 读己之写 + 共识接入验收


**需求**

1. 候补授权（队列 = 引擎内存态，键 `(day_idx, seat)`，不落日志——重启清空为已知限制）：
   RESERVE 冲突且 `enqueue_if_conflict` → 入队返 `ticket="T<seq>"`；
   任何释放（CANCEL/CHECKOUT/NO_SHOW apply 成功）→ 位图暂不释放，队首匹配者
   GRANT_OFFER + 定时器 `grant:<ticket>`（60s）；期内 GRANT_CLAIM 转 PENDING_ENTRY；
   超时顺延下一位，队空才真正释放；认领/顺延时取消旧定时器。单测 ≥10 条。
2. BREAKAWAY（中途离开）：`CheckinReq{leave=true}` → `BREAKAWAY`，
   保留期 = 11:00–13:00 / 17:00–19:00 离开 60min、其余 30min（挂时间轮）；
   期内再入馆 → 回 `IN_LIBRARY`；保留期超时 → 释放剩余片转 `LEFT`，
   释放部分进入候补授权流程。单测 ≥6 条。
3. 读己之写：`Outcome.applied_seq` 贯通（契约增量走流程）；内存有界：
   终态且过日的 booking 移出内存，幂等 LRU 生效验证。
4. 共识接入验收：T2 交付 `RaftLog : IEventLog` 后，`--consensus=raft` 双模式冒烟
   （File/Raft 切换零代码改动），配合 `failover_test.sh` 验证 `LOST=0`。
5. `arm_timers_for` 覆盖 GRANTED 授权期定时器。

**交付物**：engine 源码 PR、单测 ≥16 条、双模式冒烟记录。

**接口规范**：`Outcome.applied_seq`、`IncomingRequest` 新 kind `claim_ticket`（契约增量）。

**验收 DoD**：`make test-engine` 全绿；`failover_test.sh` 输出 `LOST=0`。

**保底**：候补授权 + 读己之写（BREAKAWAY 顺延阶段三；Raft 接入按 T2 交付节奏验收）。

## 阶段三 · 稳定性与冲刺


**需求**

1. Fuzz：随机构造非法入参（负数座位/非倍数时间/超长字符串/乱序重复请求）打
   `dispatch`；断言不崩、I1 恒成立、错误码合法；种子参数化可复现。
2. 72h 长跑 `soak.sh`：合成负载 + 每小时快照 + 每 6h `kill -9` 自动重启；
   采集 RSS 曲线 / violations / seq 连续性；自动重启 + 自动断言，无人值守。
3. `--region=N` 参数与事件 `region_id`（T3 跨区查询与 T2 双区部署的前置）。
4. 冲刺（前两项全绿后，按组长指令启动其一）：
   - `ShardEngine`：按 `seat_id % N` 分片单写者，跨片请求主分片串行；
     单线程 vs 4 分片 QPS/p99 对比，结论无论方向写入 ADR-0007；
   - 层级时间轮 v2（docs/01 §3）：接口不变替换 `TimerHeap`，超时精度/CPU 对比。

**交付物**：fuzz 测试、`soak.sh` + 72h 报告（三曲线）、冲刺对比数据页。

**验收 DoD**：fuzz 全绿；72h 报告三项指标（内存平稳 / violations=0 / seq 无洞）。

## 业务逻辑演练修订（契约 epoch 2.1，全组必读）

真实业务走查确认 8 项缺陷，引擎侧修复已合入骨架（`engine.cpp`/`mock_engine.py`）。
你的单测必须逐一覆盖以下行为（在原 ≥20 条上追加 6 条，合计 ≥26 条）：

1. 过去时段拒绝：`end_min` 对应时刻 ≤ 当前 → `E_PARAM`（防刷信用）。
2. 入馆截止夹取：`min(max(开始+30min, 早鸟保留至08:30), 时段结束)`，
   早鸟保留仅对"当日 08:00 前申请且开始 ≤ 08:30"生效（防必然爽约死锁）。
3. CHECKOUT 释放公式：m = 距当日 06:00 分钟（勿二次减 `kDayStartMin`）。
4. 定时器生命周期：签到→撤销 expire 定时器并挂 end 定时器；
   取消/NO_SHOW→撤销 expire；checkout→撤销 end；
   空转的定时器事件（竞态/重放）**不得发布**（apply 内 changed 发布守卫）。
5. 自然离馆：IN_LIBRARY 挂 `"end:<id>"` 定时器 → DONE 事件 → LEFT(+1)，
   快照恢复时重挂（`arm_timers_for` 已覆盖 IN_LIBRARY）。
6. 活跃预约唯一：handle_reserve 预检 `has_active_booking` → `E_QUOTA`。
7. SeatChanged：位图变更后追发 `SEAT_CHANGED` 事件（与业务事件同 seq，副本整字覆盖）。
8. 准入控制：in-flight 上限（1024）→ 超限回 `Shed{backoff_hint_ms}`（原遗漏项，新增）。
