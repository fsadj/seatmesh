## 阶段一 · 信用闭环与页面


**需求**

1. `gateway/credit_consumer.py`（记账规则与契约绑定）：
```python
class CreditConsumer:
    """消费 EventStream → CreditStore。
      NO_SHOW（超时未入馆）           → -10
      DONE（自然离馆，时段结束）      → +1
      CHECKOUT 且 released_mask == 0  → +1（提前离馆）
      CANCEL / 中途离开或提前离馆     →  0（不写流水）
    幂等依据 (user_id, event_seq)。"""
    def run_once(self) -> int: ...
    def run_forever(self, interval_s: float = 1.0): ...
```
2. 三条前置校验查询（注入 T3 的 app，403 请求不到达引擎）：
   信用 `balance <= -30` → `E_QUOTA`；当日已有 NO_SHOW → `E_QUOTA`（当日禁约）；
   距上次取消/爽约 <30min → `E_COOLDOWN`。签名：
```python
def pre_reserve_checks(user_id: int) -> Optional[tuple[int, str]]
```
3. `GET /api/credit` → `{balance, risk}`（挂 T3 的 app）。
4. 前端 `frontend/index.html`：登录注册、座位卡片、64 格时间条
   （06:00–22:00，`BigInt` 逐位判红/白）、预约/入馆刷卡/取消/离馆、
   5 秒轮询起步、抢座失败用 `conflict_mask` 精确提示
   （"10:15–11:00 已被占用"，BigInt 定位连续段）；请求失败显示"连接中…"不白屏。

**交付物**：`credit_consumer.py`、校验函数、前端三件套、全流程 GIF。

**验收 DoD**：`pytest gateway/tests/test_credit.py` 全绿（含三种 403 用户）；
浏览器全流程 GIF；`make demo-python` 末尾信用断言输出。

**保底**：同步 `run_once` + 无框架页面。

## 阶段二 · Saga 单区 + 管理端 + 通知 + 大屏 v1


**需求**

1. FREEZE 落日志（T1 引擎补 FREEZE 分支后你接入）：`POST /admin/freeze` →
   FREEZE 事件 → 批量置位 → 前端变灰。
2. `gateway/saga.py` SagaOrchestrator（单区，但只通过消息交互，为双区预演）：
   T1 座位 HOLD → T2 配额冻结 → T3 confirm；`SAGA_TIMEOUT=30s` 超时补偿；
   saga_id 幂等、compensate 可重入；状态存 SQLite；sweep 轮询禁 busy-wait。
3. 通知：预约成功/候补授权/过期 → 控制台 + 复用 T3 的 WS；
   事务性 outbox：业务写入与通知消息同事务（SQLite 单事务）。
4. 管理端：`POST /admin/freeze`（管理员 token）、`GET /admin/sagas`。
5. 大屏 v1 `dashboard.html`：KPI（今日预约/违约/在馆）+ 座位墙（WS 驱动、
   只重绘对应卡片）+ 热力图（`GET /api/heatmap`，ECharts，容器固定高度）。

**交付物**：`saga.py`、`admin.py`、通知模块、大屏、30s 演示 GIF。

**验收 DoD**：pytest 全绿（saga 超时补偿幂等）；"封楼→变灰→解封"演示；
座位变更 → 大屏 ≤1s（WS 路径）。

**保底**：freeze + 通知（saga 推阶段三）。

## 阶段三 · 双区 Saga + 对账 + 大屏终版


**需求**

1. Saga 双区 transport（经 T2 的跨区通道）；单区不可达 saga 挂起告警不误判。
2. 对账器 `gateway/reconciler.py`：5min 周期比对两区活跃单，全局双预约撤销
   **后到者**（判定 = 座位区事件 seq，禁止跨区时间戳）；撤销补记信用与审计事件。
3. 压测：100 用户双区并发双抢 → 全局恰好 1，3 轮全过（脚本与 T5 共用）。
4. 大屏终版：A/B 区切换 + 各区 staleness 标注 + 失联区置灰横幅 + KPI 扩充
   （候补队列长度、saga 在途数）+ 预测曲线叠加（T5 forecast 就绪后接入）。
5. 可选增强：移动端适配（面板响应式）。

**验收 DoD**：双抢 3 轮各"恰 1"；对账演练输出；大屏对照答辩四数据点可视化打勾。

**保底**：对账手动触发版；预测曲线静态快照。
