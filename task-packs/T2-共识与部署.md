## 阶段一 · Raft 练手库


**需求**

1. 独立目录 `raft/`（零外部依赖）。消息：RequestVote / AppendEntries 两族 +
   `LogEntry{term, cmd}`；`RaftNode` 三状态，全部由外部 `tick()` 驱动（禁止 sleep）。
2. 选举超时 300–600 tick，**每次状态变化重新随机**。
3. 持久化 `currentTerm/votedFor/log` 到本地文件（带 CRC），重启不重复投票。
4. 日志复制 `nextIndex/matchIndex`；提交规则 = 多数派 + 当前任期条目（§5.4.2）。
5. 确定性仿真 `SimCluster`：3 节点 + 种子化延迟队列（1–10 tick）+ 可丢消息；
   同一种子必得同一执行轨迹。
6. 测试五场景：选举收敛 / 复制一致（leader 写 10 条全员 apply 序列一致）/
   kill leader 不丢已提交 / 2-1 分区少数派不提交 / 节点重启恢复。

**交付物**：`raft/` 库 + `test_raft.cpp` + Makefile 目标 `test-raft`。

**验收 DoD**：五场景全绿；输出 10 个种子的选举收敛 tick 统计。

**保底**：前两条场景（选举 + 复制）。

## 阶段二 · RaftLog 接入主链路


**需求**

1. `RaftLog final : seatmesh::IEventLog`：`append` = propose → 多数派确认 →
   回调 apply（本地 append 未提交不得 apply）；`replay` = 本地日志重建，
   尾部未提交条目丢弃。
2. `InstallSnapshot`：leader 全量快照推给滞后 follower（快照 provider 由引擎注入，
   与 FileEventLog 同机制）。
3. 传输真实化：ZMQ 或 TCP 承载 RaftMessage（帧带 CRC）；SimCluster 测试保留进 CI。
4. 接入：`main.cpp` 增加 `--consensus=raft --id --listen --peers`；
   非 leader 对写请求回 `{"redirect":"<leader>"}`。
5. `engine/scripts/failover_test.sh`：3 节点压测 30s → `kill -9` leader →
   输出 `COMMITTED=... LOST=0 ELECTION_P99=...ms`（目标 P99 <600ms）。
6. 双 leader 并存窗口：旧 leader 未提交提案按 term 丢弃（写成确定性测试）。

**交付物**：`raft/` 接入代码、CLI 参数、failover 脚本与统计。

**接口规范**：`RaftLog` 对外与 `IEventLog` 完全一致（评审现场对照契约）。

**验收 DoD**：`LOST=0` 输出 + `make test-raft` 不回退。

**保底**：接入与 failover 脚本（InstallSnapshot 顺延，滞后 follower 走全量重放替代）。

## 阶段三 · 双校区部署与断网剧本


**需求**

1. `deploy/docker-compose.yml`：region-A（3 引擎+网关+观察）/ region-B（2 引擎+网关）
   两套网络；服务命名 `engine-a1..a3 / gateway-a / engine-b1,b2 / gateway-b / bridge`；
   资源限额显式声明。
2. `deploy/tc.sh`：跨区流量 `netem delay 10ms`，支持丢包注入（桥接容器 NET_ADMIN）。
3. Makefile：`make up`（全新机器 ≤5 分钟）/ `down` / `chaos-split` / `chaos-heal`。
4. `sre/chaos/c2_split.sh`：断网 → 两区自治正常 → 恢复 → 事件追平对账一致；
   连续三次执行结果一致。
5. InstallSnapshot 滞后项（若阶段二未完成）在本阶段收尾。

**验收 DoD**：`make up` 计时截图；`c2_split.sh` 三次执行输出一致。

**保底**：单 compose 同机双端口模拟两区（去掉 tc）。
