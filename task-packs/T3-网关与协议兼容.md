## 阶段一 · 网关骨架


**需求**

1. `gateway/app.py`：`create_app(engine: EngineClient, stream: EventStream)` 工厂；
   业务路由只依赖 `contracts.py` Protocol。
2. 鉴权：register/login；SQLite `users` 表（sha256(salt+password)）；
   token = `user_id.过期时间戳.hmac(...)`；`Authorization: Bearer` 校验。
3. 业务 API 表（T4/T5 的消费契约，冻结后走流程）：

   | Method | Path | 请求体 | 200 响应 | 错误 |
   |---|---|---|---|---|
   | POST | /auth/register | `{username,password}` | `{user_id}` | 409 |
   | POST | /auth/login | `{username,password}` | `{token,user_id}` | 401 |
   | POST | /api/reserve | `{seat_id,day_off,start_min,end_min}` | `{ok,booking_id,conflict_mask,detail}` | 401/403/429 |
   | POST | /api/bookings/{id}/cancel | `{}` | `{ok,detail}` | 401/404 |
   | POST | /api/bookings/{id}/checkin | `{qr_token,leave}` | `{ok,detail}` | 401/404 |
   | POST | /api/bookings/{id}/checkout | `{}` | `{ok,released_mask}` | 401/404 |
   | GET | /api/seats?day_off=1 | - | `{seats:[{seat_id,bits}],last_seq,stale}` | 401 |

   `conflict_mask/bits/released_mask` 一律**十进制字符串**；403 = 前置校验拒绝
   （`E_QUOTA`/`E_COOLDOWN`，校验函数由 T4 注入）。
4. 限流：per-user 令牌桶（5 rps / burst 20）→ 429 + `Retry-After`。
5. `pre_reserve_checks` hook（依赖反转）：app 工厂接受 `checks: list[CheckFn]`，
   reserve 前逐个调用，任一返回 `(code, detail)` 即 403——你只定义接口，T4 注入实现：
```python
CheckFn = Callable[[int], Optional[tuple[int, str]]]
# 入参 user_id；返回 None=放行
```
6. 组装：默认 MockEngine；`SEATMESH_ENGINE=zmq` 切 `ZmqEngineClient`
   （与 T1 联调 JSON 帧格式 v0，签字后冻结）。
7. 测试 `gateway/tests/test_api.py`：全流程 200、每条错误码、限流 429、
   100 线程抢同一座位恰好 1 成功。

**交付物**：`app.py`、`auth.py`、`tests/test_api.py`、`requirements.txt`、Makefile `test-api`。

**验收 DoD**：`make test-api` 全绿；uvicorn 起服务 curl 走通全流程（截图）。

**保底**：无鉴权 5 个业务 API + 正例测试。

## 阶段二 · 副本完善与实时通道


**需求**

1. `ReplicaView` 升级：最近 10 万事件环形缓冲；seq 缺口检测（seq > last_seq+1）→
   SnapshotPull（`GET /internal/snapshot`，引擎侧由 T1 暴露）→ 拉取期间
   `degraded=True`，查询响应 `"stale": true`。
2. WebSocket `/ws/seats?day_off=`：帧 `{"type":"seat_changed","seat_id":3,
   "day_off":1,"bits":"65280","seq":42}`（T4 前端消费）；重连 0–5s 随机抖动，
   防引擎重启重连风暴。
3. leader 跟随：`ZmqEngineClient` 处理 redirect，缓存 TTL 5s；全节点不可达 503。
4. single-flight：同一 (day_off, 座位区间) 的并发查询合并为一次副本读。
5. 前置校验接入：T4 的三规则校验函数（信用 ≤-30 → `E_QUOTA`；当日 NO_SHOW →
   `E_QUOTA`；冷却期 → `E_COOLDOWN`）经 hook 生效，403 请求不到达引擎。
6. 测试 ≥10 条：kill 引擎 30s 查询正常；恢复 3s 内 stale 归零；WS 不丢帧；redirect 生效。

**交付物**：`replica.py`、`ws.py`、`zmq_engine.py` redirect、测试。

**验收 DoD**：`pytest gateway/tests/test_replica.py` 全绿；kill 引擎演练录屏。

**保底**：轮询版副本 + degraded 标注（WS 推阶段三）。

## 阶段三 · 跨区查询与 compat 端点


**需求**

1. `GET /api/seats/all?day_off=`：按 RouteTable 并发请求各区网关
   （`return_exceptions=True`，单区 200ms 超时）；响应带
   `regions_staleness`（ms）；单区不可达标 `unavailable`，其余正常（降级语义入契约附录）。
2. compat 同形端点（规格 = `docs/compat-notes.md` §四，平行实现，BASE_URL 指向自身）：
   `/qspace`、`/qseat?sp=`（status 由副本位图推算）、`/seat/?kid=&sp=`（映射为
   当日全片预约）、`/my/`、`/my/?cancel=1&ri=`、`/history/`；
   `scripts/compat_demo.sh` 输出 curl 序列与映射表对照。

**验收 DoD**：B 区不可达时 A 区查询仍 200 且标注；compat 用例全绿。

**保底**：串行查询两区 + compat 四条端点。
